# 독립 모델과 자원 회귀 검사

## 작은 상태 공간은 전부 돈다

`tests/run_tests.py`는 2~5개 입력의 모든 152개 순열을 생성한다. 각 입력에서
`push_swap` 명령을 독립 Python 모델로 적용하고, 원소 보존·정렬·B의 빈 상태를
확인한다. 같은 명령을 실제 checker에도 전달해 `OK`인지 확인한다.

큰 입력은 정해진 seed와 LCG shuffle로 중복 없는 수를 만든다. 크기
2, 3, 5, 6, 17, 64와 seed 다섯 개는 같은 입력을 두 번 실행해 명령열까지 같은지
본다. 100개는 1,500개, 500개는 8,000개 명령 상한도 별도로 둔다.

## 공통 코드 밖에 독립 oracle을 둔다

생성기와 checker가 C 연산 구현을 공유하므로 둘만 서로 검사하면 같은 rotate 버그를 정답으로 받아들일 수 있다. Python 리스트 모델은 C 배열 이동 코드를 사용하지 않아 공통 실패 가능성을 낮춘다.

연산 단위 C 테스트, 독립 모델, 실제 checker의 세 층이 서로 다른 경계를 확인한다.

## 자원 기준은 알고리즘 퇴행을 찾는다

`tests/resource_tests.py`는 크기 10, 100, 500과 seed 세 개에서 다음 값을
`tests/resource_baseline.json`과 비교한다.

- stdout 명령 수와 내부 `PS_OPERATIONS`가 같은지
- 이동하거나 다시 쓴 `(value, rank)` 쌍의 논리적 수
- 계측 헤더를 제외한 프로젝트 할당 바이트 중 동시에 살아 있는 최댓값
- 종료 시 살아 있는 프로젝트 할당이 0인지

크기 500의 현재 기준은 명령 6,784개, 배열 이동 최대 3,200,000쌍,
동시 할당 최대 8,000바이트다. 실행 시간은 출력하지만 판정에는 사용하지 않는다.
같은 정답을 내더라도 매 비트마다 배열을 불필요하게 더 움직이거나 명령마다
할당하는 변화가 들어오면 드러난다.

```sh
make test
make sanitize
```

기준을 바꿀 때에는 숫자만 갱신하지 말고 명령 수와 이동량의 교환 관계를
설명할 수 있어야 한다. 계측은 `ps_malloc`과 연산 함수의 논리적 이동만 보므로
libc, Python, `qsort` 내부 할당과 실제 `memmove` 바이트 수는 포함하지 않는다.
`make sanitize`도 연산 불변식과 기능 property를 실행하지만 fault·자원 회귀
스크립트까지 sanitizer로 반복하지는 않는다.
