# 값과 순위의 표현 불변식

## 두 배열의 같은 인덱스는 한 원소다

배열 기반 스택은 원래 값과 좌표 압축한 순위를 별도 메모리에 둔다. 정렬 분기는
`rank`를 보고, 검증과 오류 출력에는 원래 `value`가 남는다. 연산 하나라도 한쪽
배열만 움직이면 정렬 판단과 실제 원소가 갈라진다.

`src/operations.c`의 swap은 두 값을 같은 순서로 바꾼다.

```c
value = stack->values[0];
rank = stack->ranks[0];
stack->values[0] = stack->values[1];
stack->ranks[0] = stack->ranks[1];
stack->values[1] = value;
stack->ranks[1] = rank;
```

push는 목적지의 두 배열을 한 칸 열고 쌍을 넣은 뒤 원본 두 배열을 당긴다.
rotate와 reverse rotate도 첫 원소나 마지막 원소의 값과 순위를 함께 임시
보관한다. 크기가 0이나 1인 swap·rotate는 아무 일도 하지 않는다.

## 원소 보존을 상태마다 확인한다

최종 정렬만 검사하면 중간에 원소를 잃었다가 중복 값으로 채워도 특정 입력에서 통과할 수 있다. C 테스트는 각 연산 뒤 다음 조건을 확인한다.

- A와 B의 총 크기가 변하지 않았는가
- 모든 원래 `(value, rank)` 쌍이 정확히 한 번 존재하는가
- 각 스택의 `size`가 0과 `capacity` 사이인가
- 결합 연산 `ss`, `rr`, `rrr`이 양쪽에 같은 기본 의미를 적용했는가

자료구조를 연결 리스트로 바꾸더라도 이 불변식은 그대로 재사용할 수 있다.

`tests/operation_invariants.c`는 고정된 다섯 `(value, rank)` 쌍에 11개 명령을
하나씩 적용하고, 결합 명령과 연속 명령에서도 원소가 정확히 한 번씩 남는지
확인한다. 출력 없는 `emit=0` 경로를 사용해 자료구조 연산만 분리한다.

## 좌표 압축 실패도 원래 스택을 정리한다

`src/parser.c`는 정렬 복사본을 만들고 `qsort` 뒤 인접 값으로 중복을 찾는다.
각 원래 값은 이 정렬 배열의 lower bound 위치를 순위로 받는다. 작은 값부터
0..N-1이 되므로 radix 정렬은 음수 원본을 따로 다룰 필요가 없다.

정렬 복사본 할당이 실패하거나 중복을 찾으면 복사본과 이미 만든 스택의 두 배열을
모두 정리한다. `stack_init`도 두 번째 배열 할당이 실패하면 첫 번째 배열을
`stack_free`로 되돌린다.

```sh
make test
```

현재 숫자 parser는 각 자리를 반영한 뒤 `int` 한계를 검사한다. 반복이 계속된다면
직전 값은 양수 `INT_MAX`, 음수 `INT_MAX + 1` 이하이다. 32비트 `int`인 현재
검증 환경에서 다음 누적식의 최댓값은 `21474836489`로 `LLONG_MAX`보다 작으므로,
매우 긴 숫자열도 `long long` 오버플로에 도달하기 전에 `int` 범위 초과로
거절된다. 다만 `tests/run_tests.py`는 `2147483648`과 `-2147483649`처럼 경계
바로 밖의 값만 고정하며 초장문 숫자열 자체는 회귀 사례로 두지 않는다. 좌표
압축도 정렬 복사본과 두 스택 배열만 계측하며 `qsort` 내부 자원은 추적하지 않는다.
