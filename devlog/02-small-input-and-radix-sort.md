# 작은 경우를 닫고 기수 정렬로 넓히기

스택 연산을 만든 다음 바로 큰 입력 알고리즘부터 붙이지 않았다. `sort.c`의
커밋 흐름은 최솟값의 위치를 찾고 맨 위로 옮기는 도구, 2~3개 전용 정렬, 4~5개
정렬, 기수 정렬 순서다. 입력 수에 따라 서로 다른 전략을 쓰지만 바깥에서는
`sort_stack` 하나만 호출한다.

```c
int	sort_stack(t_stack *a, t_stack *b)
{
	if (a->size < 2 || stack_is_sorted(a))
		return (1);
	if (a->size <= 5)
		return (sort_tiny(a, b));
	return (radix_sort(a, b));
}
```

정렬된 입력을 먼저 끝내는 분기는 단순한 최적화 이상의 의미가 있다. 출력이 없는
것도 올바른 명령열이며, 뒤의 알고리즘이 불필요한 명령을 만들지 않는다는 CLI
계약을 고정한다.

## 세 원소는 여섯 순서를 직접 닫는다

두 원소는 첫 순위가 더 클 때만 `sa`를 내보낸다. 세 원소부터는 가능한 순서가
여섯 개뿐이라 첫째·둘째·셋째의 관계를 직접 구분했다. 예를 들어 첫 원소가
최댓값, 둘째가 최솟값, 셋째가 중간값인 `[최대, 최소, 중간]` 순서라면 `ra`
한 번으로 `[최소, 중간, 최대]`가 된다.

```c
else if (first > second && second < third && first > third)
	return (op_ra(a, 1));
```

분기 하나가 빠져도 임의 입력 몇 개만으로는 찾기 어렵다.
`tests/run_tests.py`는 2~5개 입력의 모든 순열을 돌린다. 생성된 명령을 Python
리스트 모델에 적용하고 실제 `checker`에도 전달하므로, 결과가 정렬됐는지와
프로그램끼리 같은 명령 의미를 쓰는지를 함께 확인한다.

4~5개에서는 가장 작은 순위를 B로 잠시 옮긴다. 최솟값이 A의 위쪽 절반에 있으면
`ra`, 아래쪽에 있으면 `rra`가 적게 든다.

```c
if (index <= a->size / 2)
{
	while (index-- > 0)
	{
		if (!op_ra(a, 1))
			return (0);
	}
}
else
{
	index = a->size - index;
	while (index-- > 0)
	{
		if (!op_rra(a, 1))
			return (0);
	}
}
```

최솟값을 순서대로 빼면 A에 남은 세 원소는 전용 분기로 닫을 수 있다. B에는 큰
최솟값을 먼저 넣고 더 작은 값이 그 위에 쌓이므로, 마지막에 `pa`만 반복하면
오름차순 앞부분이 복원된다.

## 큰 입력은 값이 아니라 rank의 비트를 본다

원래 정수에는 음수와 큰 양수가 섞인다. 앞 단계에서 값을 `0..n-1` 순위로
바꾼 덕분에 부호 표현을 따로 처리하지 않고 필요한 비트 수를 `n-1`에서 구할 수
있다.

`radix_sort`는 낮은 비트부터 한 라운드씩 처리한다.

```c
round_size = a->size;
i = 0;
while (i < round_size)
{
	if (((a->ranks[0] >> bit) & 1) == 1)
	{
		if (!op_ra(a, 1))
			return (0);
	}
	else if (!op_pb(a, b, 1))
		return (0);
	i++;
}
while (b->size > 0)
{
	if (!op_pa(a, b, 1))
		return (0);
}
```

라운드 도중 A의 크기는 줄어들기 때문에 반복 조건에 `a->size`를 그대로 쓰면
처리하지 않은 원소를 남길 수 있다. 시작할 때 잡아 둔 `round_size`만큼 정확히
소비해야 한다. 비트가 1인 원소는 `ra`로 기존 상대 순서를 유지하고, 0인 원소도
B에 쌓였다가 전부 A로 돌아오면서 원래 순서가 복원된다. 이 안정성이 앞서 처리한
낮은 비트의 순서를 다음 라운드까지 보존한다.

이 선택은 최단 명령열 탐색이 아니다. 입력 크기에 따라 예측 가능한 라운드 수와
단순한 정확성 근거를 얻는 대신, 배열 스택의 `push`와 `rotate`가 매번 여러
원소를 옮긴다. 그래서 `tests/resource_tests.py`는 명령 수뿐 아니라
`PS_ARRAY_MOVEMENTS`도 기록한다. 연결 리스트나 원형 버퍼로 바꾸면 같은 명령
전략이라도 메모리 이동 비용은 달라진다.

출력 실패도 정렬 함수의 반환값을 따라 즉시 올라간다. 메모리 안의 A와 B가
정렬됐더라도 소비자가 완전한 명령열을 받지 못했으면 성공이 아니다. 이 경계는
[제한된 명령 입력과 출력 실패](03-command-io-and-failures.md)에서 이어진다.
