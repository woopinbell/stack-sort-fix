# stack-sort

두 개의 스택과 정해진 11개 연산만 사용해 정수 목록을 오름차순으로 정렬합니다. `push_swap`은 명령열을 만들고, `checker`는 같은 입력에 명령열을 적용해 결과를 판정합니다.

## 빌드와 실행

```sh
make
./push_swap 3 2 1
./push_swap "3 2 1" | ./checker "3 2 1"
```

`checker`는 A가 정렬되고 B가 비어 있으면 `OK`, 아니면 `KO`를 출력합니다. 잘못된 입력, 명령, 읽기·쓰기 실패는 `Error`와 0이 아닌 종료 코드로 알립니다.

지원 명령은 `sa`, `sb`, `ss`, `pa`, `pb`, `ra`, `rb`, `rr`, `rra`, `rrb`, `rrr`입니다. 검사기의 명령은 개행을 제외하고 최대 3바이트이며 마지막 개행은 생략할 수 있습니다. 빈 줄, NUL이 든 입력, 긴 토큰은 거절합니다.

## 입력과 정렬

여러 argv 안의 공백 구분 토큰을 모두 읽습니다. 값은 32비트 C `int` 범위여야 하고 중복될 수 없습니다. 파싱 뒤 상대 순서를 보존하는 `0..n-1` 순위로 변환합니다.

- 이미 정렬됨: 출력 없음
- 2~5개: 작은 입력 전용 분기
- 6개 이상: 낮은 비트부터 처리하는 안정적인 LSD 기수 정렬

이 구현은 모든 입력의 최소 명령열을 탐색하지 않습니다. 같은 크기의 비정렬 입력은 기수 정렬에서 같은 수의 라운드를 사용합니다.

## 검증

```sh
make test
make sanitize
```

C 테스트는 모든 연산 뒤 `(value, rank)` 대응과 원소 보존을 확인합니다. Python 테스트는 2~5개 전체 순열과 고정 시드 입력을 독립 모델로 실행하고 실제 checker 결과와 비교합니다. 별도 검사는 `malloc`, `read`, `write` 실패, `EINTR`, 짧은 쓰기, 닫힌 파이프와 명령·배열 이동·할당량 기준을 확인합니다.

생성기와 검사기의 관계는 [생성부터 검증까지](architecture/generator-and-checker.md), 정렬 선택과 비용은 [정렬 전략과 연산 비용](architecture/sorting-and-operation-cost.md)에 정리했습니다. 실제 장애 지점은 [개발 기록](devlog/README.md)에서 찾을 수 있습니다.

검사기는 blocking stdin을 전제로 하며 `EAGAIN`을 기다리지 않습니다.
