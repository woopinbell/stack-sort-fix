# 정렬 전략과 연산 비용

## 좌표 압축

실제 값의 크기는 정렬 전략에 필요하지 않고 상대 순서만 필요하다. 예를 들어 `[-20, 500, 7]`은 `[0, 2, 1]`이 된다. 중복 검사를 같은 정렬 배열에서 수행할 수 있고, 기수 정렬은 음수 표현이나 큰 값의 비트 수에 영향받지 않는다.

값과 rank 배열은 같은 이동을 공유하므로 정렬 뒤에도 원래 값이 보존된다.

## 작은 입력

2개는 필요한 경우 `sa` 한 번으로 끝낸다. 3개는 맨 위 세 순위의 관계를 여섯 경우로 나눠 `sa`, `ra`, `rra` 조합을 고른다.

4~5개는 가장 작은 rank를 찾아 위쪽과 아래쪽 중 가까운 방향으로 회전한 뒤 B로 옮긴다. A에 세 개가 남으면 전용 정렬을 적용하고 B의 최솟값을 A로 다시 올린다.

작은 입력에서 일반 기수 정렬을 쓰지 않는 이유는 정확성 때문이 아니라 명령 수 때문이다. 모든 순열을 독립 모델로 검사할 수 있어 분기 누락도 찾기 쉽다.

## LSD 기수 정렬

6개 이상은 rank의 낮은 비트부터 본다. 각 라운드 시작 시 A의 크기를 고정하고 그 수만큼만 처리한다.

- 해당 비트가 1: `ra`로 A 뒤로 이동
- 해당 비트가 0: `pb`로 B에 보관
- 라운드 끝: B를 전부 `pa`로 A에 복귀

이 과정은 이전 비트에서 만들어진 순서를 보존한다. 필요한 비트 수는 최대 rank인 `n-1`로 계산한다.

## 비용은 여러 축으로 본다

명령 수만 줄어도 배열 구현의 원소 이동량이 크게 늘 수 있다. 이 저장소는 다음 값을 따로 측정한다.

- 출력한 연산 수
- swap, push, rotate가 옮긴 배열 원소 수
- 동시에 살아 있는 프로젝트 할당 바이트의 최댓값
- 최종 출력 바이트와 checker 결과

벽시계 시간은 머신 부하에 따라 달라지므로 참고값일 뿐 합격 조건으로 쓰지 않는다. 자료구조나 정렬 전략을 바꿀 때에는 어떤 비용을 줄이고 어떤 비용이 늘었는지 함께 비교해야 한다.
